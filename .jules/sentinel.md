## 2026-02-26 - Docker Container Running as Root
**Vulnerability:** The `Dockerfile.sandbox` for the local code execution sandbox was configured to run the container process as `root` by default. This meant that any code executed within the sandbox (including untrusted user code) ran with root privileges inside the container. If a container escape vulnerability existed or if the host filesystem was mounted without proper isolation (which was the case with `--network=host` and volume mounts), the attacker could easily escalate privileges and compromise the host system.
**Learning:** Default Docker images (like `python:3.13-slim-bookworm`) run as root unless a `USER` instruction is specified. This is a common oversight in Dockerfiles, especially when focusing on functionality over security. The `start_local_sandbox.sh` script also mounted the host directory, exacerbating the risk.
**Prevention:** Always include a `USER` instruction in Dockerfiles to switch to a non-root user (e.g., `sandbox` with UID 1000) before the `CMD` or `ENTRYPOINT`. Ensure that necessary directories (like `/app` and `/workspace`) are owned by this user or writable by the group if needed, but prefer read-only application code where possible.
