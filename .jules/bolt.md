## 2024-10-24 - [Optimize JSON validation]
**Learning:** When optimizing JSON validation, use a 'try-parse first' strategy instead of blanket string replacements (e.g., replacing single quotes with double quotes) before parsing. This prevents corrupting valid JSON that legitimately contains the replaced characters and avoids performance overhead on the happy path.
**Action:** Always attempt to parse the original string first. Only fallback to quote replacement and a second parse attempt if the initial parse fails and single quotes are actually present in the string.
## 2025-05-18 - Optimized closest regex match lookup by avoiding O(N) list allocation
**Learning:** For algorithms trying to find a matching regex closest to a specific target point (like finding a sentence boundary closest to the midpoint of a string), calling `list(re.finditer(...))` followed by `min()` forces an unnecessary $O(N)$ memory allocation and a full scan of the entire string, which is highly inefficient for large texts. Because `re.finditer` is evaluated lazily and the matched positions (e.g. `match.end()`) strictly increase as we scan from left to right, the calculated absolute distance from the midpoint will monotonically decrease until it hits the minimum, and then monotonically increase thereafter.
**Action:** Always prefer iterating over `re.finditer` lazily in a `for` loop, tracking the minimum distance. As soon as the calculated distance starts to increase (i.e. `distance > min_distance`), short-circuit the loop using `break`. This completely avoids scanning the second half of large strings and keeps the memory complexity at $O(1)$.
