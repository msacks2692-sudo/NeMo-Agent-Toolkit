## 2024-10-24 - [Optimize JSON validation]
**Learning:** When optimizing JSON validation, use a 'try-parse first' strategy instead of blanket string replacements (e.g., replacing single quotes with double quotes) before parsing. This prevents corrupting valid JSON that legitimately contains the replaced characters and avoids performance overhead on the happy path.
**Action:** Always attempt to parse the original string first. Only fallback to quote replacement and a second parse attempt if the initial parse fails and single quotes are actually present in the string.
## 2024-11-20 - [Optimize DPO Trajectory Builder Candidate Collection]
**Learning:** In highly nested, tight loops inside metric-heavy code (like `trajectory_builder.py`), avoiding intermediate dictionary/map allocations (`input_items_map = {item.id: item for item in list}`) and caching dictionary values (like metric counts) to local variables (`total_candidates = self._metrics.get(...)`) before iterating can yield ~10-11% performance improvements by preventing redundant dictionary access overheads. Furthermore, using a `try: ... except KeyError:` pattern instead of `if key not in dict:` can be marginally faster for list appending in dictionary groups.
**Action:** When working on tight nested loops processing thousands of elements (like trajectory step loops), avoid creating intermediate data structures solely for iteration and lift heavily accessed dictionary values into local loop variables.
