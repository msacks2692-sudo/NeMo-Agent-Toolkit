## 2024-10-24 - [Optimize JSON validation]
**Learning:** When optimizing JSON validation, use a 'try-parse first' strategy instead of blanket string replacements (e.g., replacing single quotes with double quotes) before parsing. This prevents corrupting valid JSON that legitimately contains the replaced characters and avoids performance overhead on the happy path.
**Action:** Always attempt to parse the original string first. Only fallback to quote replacement and a second parse attempt if the initial parse fails and single quotes are actually present in the string.
## 2024-05-18 - Pre-compile Regex at Module Level
**Learning:** Functions called frequently (like `remove_r1_think_tags` in this project) can incur unnecessary overhead if they compile regex strings dynamically on every call (e.g., via `re.match` with a string pattern). While the internal Python `re` cache mitigates this somewhat, direct method calls on a pre-compiled `re.Pattern` object avoid dictionary lookups and are measurably faster.
**Action:** Always inspect high-frequency text-processing utility functions for dynamic regex compilation. Pre-compile these at the module level using `re.compile()` to eliminate repeated overhead. Also, remember to add code comments explaining the optimization as per the persona rules!
